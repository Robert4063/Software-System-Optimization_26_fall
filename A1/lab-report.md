## 3. 请求链路解释

以 `curl -s http://127.0.0.1:8000/health` 为例，请求链路可以解释为：

1. **客户端发起请求。** `curl` 根据 URL 向 `127.0.0.1` 的 TCP 8000 端口建立连接，并发送包含 `/health` 路径的 HTTP GET 请求。响应记录中的 `Host: 127.0.0.1:8000` 和 `User-Agent: curl/8.5.0` 支持这一点。
2. **地址与端口确定目的地。** `127.0.0.1` 是回环地址，请求在客户端所在网络命名空间内进行本地通信；8000 是目标服务端口。本次请求没有经过另一台机器或公网。
3. **操作系统网络栈把连接交给监听套接字。** Linux 网络栈处理本地 TCP 通信，目的地址和端口与服务的监听套接字匹配。`ss` 输出中的 `0.0.0.0:8000`、`pid=854`、`fd=3` 将端口、套接字和 Python 进程关联起来。
4. **服务进程执行 HTTP 请求处理逻辑。** PID 854 的 `server.py` 进程接收请求，由其 HTTP 请求处理逻辑读取路径和请求头，组织包含主机名、工作目录及系统信息的响应，再通过连接返回给 `curl`。记录没有提供 `server.py` 源码，因此无法进一步确认处理函数名称或线程模型。
5. **服务输出日志，终端保存日志。** 本次请求在服务端产生 `[2026-09-18 14:04:15] GET /health HTTP/1.1` 记录。启动命令中的 `2>&1` 合并标准错误与标准输出，`tee` 将输出同时显示在终端并写入 `starter/evidence/server.log`。

**结论：** 请求路径、请求时间、PID 和端口记录共同支持“客户端 → 回环地址与端口 → Linux 网络栈 → Python 服务进程 → HTTP 请求处理逻辑 → 响应及日志”的链路。这里的网络栈和处理逻辑说明是依据 HTTP/TCP 工作方式及现有输出作出的解释，本次没有进行抓包或函数调用追踪。
